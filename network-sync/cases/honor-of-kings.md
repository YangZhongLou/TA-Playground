# 王者荣耀

主线：**服务器按固定节拍广播输入的帧同步**（乐观锁步）。

网上走的是「这一拍谁点了什么」，不是「每个小兵现在在哪」。
十台手机会拿到同一串输入，各自用同一套逻辑算出同一局。服务器不负责把每个小兵的坐标当权威广播出去。

它不是保守锁步：不等最慢的那个人到齐才开下一拍。
它也不是状态同步：伤害和位移在每个客户端的逻辑层算，不在服务器算完再下发结果。

公开来源：天美 L1 技术总监孙勋，TGDC / 腾讯游戏学堂复盘。
66ms 一拍、UDP 冗余、不同步 Hash、放弃过的方案，都来自这次分享。

## 先记住三句话

1. 对战核心每秒 **15** 个逻辑拍（每拍 66ms）。这 15 个包不能少、不能乱序。
2. 画面可以 60fps。那是表现层在两拍逻辑之间插值，不是逻辑真的跑 60 次。
3. 收到第 n 拍就立刻执行，不再额外攒 buffer。网差一点的人觉得自己迟，不应拖慢全场。

孙勋把客户端逻辑层叫做「本地的 Server」：十个人同一份输入，必须得到同一世界。
浮点、真随机、程序员随手写的本地逻辑，都会让十个世界慢慢分叉。

## 一局里各台机器干什么

| 层 | 干什么 |
| --- | --- |
| PvP 服务器 | 按 66ms 收齐（或不齐也到点）输入，编成有序号的帧，广播；丢了就补；做 Hash 校验 |
| 客户端逻辑层 | 按帧号执行输入，推进英雄、小兵、技能、伤害。必须与其他九台一致 |
| 客户端表现层 | 把逻辑位置抄过来插值、播动画。抖不抖只影响观感，不影响结算 |

大厅、匹配、排行不是帧同步。那是普通服务端状态。只有进了 PvP 房间，才走输入帧。

## 点一下技能：逐步发生什么

1. **你点了技能。**
   客户端把这次操作做成输入，尽快发给服务器。此时逻辑层还没有「技能已经结算」。
2. **服务器的节拍器到了（每 66ms 一次）。**
   把这一拍里收到的所有人输入打包，标上帧号 n，发给十个客户端。
   某人本拍没包到达，这一拍就按空输入或上一拍策略处理，**节拍照样往前**。
3. **你的逻辑层执行帧 n。**
   十台机器用同一套定点运算、同一随机种子序列，算出技能是否命中、伤害多少、人被击退到哪。
   理论上十份结果相同。
4. **表现层跟上。**
   模型、特效按逻辑态插值。你可以 60fps 看到平滑位移，结算仍停在 15Hz 的逻辑拍上。
5. **若帧 n 的包丢了。**
   不能跳去执行 n+1。帧同步要求 1,2,3,4,5 严格按序。
   服务器按编号从内存补发；平时每个下行包还带着前几拍的冗余，空口丢一包往往下一包就能补上。

和守望先锋的差别：你按下技能到「逻辑承认这一下」，至少要等到服务器那一拍广播回来。
没有「本地先把技能结算掉再等服务器」。孙勋试过类似 C/S 的本地先动，角色发飘，放弃了。

和 Dota 2 的差别：小兵走到哪不是服务器告诉你的坐标，是你这台手机算出来的。
所以同屏近 100 个单位，网上仍然主要是十个人的操作。

## 为什么当初不用状态同步

前作《霸三国 OL》就是 Client-Server：服务器判定，客户端表现。更安全，丢包也能靠下一份结果补。
王者改帧同步，是产品约束，不是「MOBA 必须锁步」。

**带宽。** 同屏将近 100 个单位。一个 AOE 打中 20 人再挂 debuff，若发状态，这些结果都要下行。
帧同步只发十个玩家的操作。孙勋给的账：理论 15 拍/秒、20 分钟录像约 10MB，外网 5v5 大约 3MB。

**工期。** 端游做一个英雄技能要对齐「客户端表现」和「服务器判定」，要两三周。
王者从预研到技术测试大约三四个月，还从 UE 换成 Unity、代码不搬。
帧同步让技能只写一套逻辑，表现层镜像。C/S 管线当时来不及。

孙勋举例「dota、星际」用帧同步，说的是 **Dota 1 / 星际争霸**。
Dota 2 已是 Source 状态同步，见 [dota2.md](dota2.md)。

## 乐观：不等最慢的人

经典锁步（囚徒模式）：任一端输入没到，全场停在这一拍。一个人卡，十个人看加载。

王者：节拍由服务器打。到点就广播。网差的人感到自己的操作晚进世界；
网好的人继续按 15Hz 往前走。这叫乐观锁步 / 服务器定时驱动。

他们试过「一有输入就染色编号立刻下发」，不再卡死 15 包/秒。
手感几乎没涨，包量跟每个人的手速走，手机发烫。于是锁死 15Hz。

也试过传统帧同步的延迟投递（先攒几拍再演，抗抖动）。
抗抖确实好，动作向英雄手感偏钝，放弃。最终是：**零额外 buffer，到了就演**。
下一拍迟到时会卡一下。用表现插值和冗余包去补，而不是用输入延迟去藏。

## 逻辑层如何保证十台算一样

| 禁止 | 原因 |
| --- | --- |
| 浮点当逻辑 | 不同 CPU / 编译器结果可能分叉 |
| 真随机 | 各端会随机出不同暴击 |
| 逻辑里读本机时间、读表现层 | 十台「现在」不同 |
| 无序容器遍历当逻辑顺序 | 哈希顺序不稳定 |
| 随手写仅本地生效的伤害 | 十个平行宇宙 |

随机改用开局种子：第 N 次伪随机，十台相同。
碰撞和基础数学用自研、整型化的库。动画可以 60fps，但不能反过来驱动伤害。

表现层只 Copy 逻辑态再插值。逻辑 15Hz、渲染 60Hz 完全可以并存。
「王者只有 15 帧」若指画面，是误读；指结算节拍，才对。

## 传输

先用过 TCP。局域网还行。外网一丢包，窗口和慢启动会让重连非常卡，改 UDP。
可靠性放到应用层：

- 输入存在服务器内存，按帧号补发。
- 默认每个下行包冗余前 3 拍；丢包严重就加冗余。
- 大于 MTU 的包在 App 层拆开，丢了补碎片，避免整包蒸发。

重连不能只吃「当前镜像」。必须从开局把中间逻辑拍跑完（可快进、压缩执行）。
这比 Dota 2 拉一份快照慢，是帧同步的结构税。崩溃重连会打 CPU。

## 不同步是什么、怎么抓

十台结果一旦不一样，叫不同步。来源：逻辑写到本地旁路、浮点临界、或修改器。
服务器定时抽关键状态做 Hash，对不上的人就被标出来。

上线时大约 2% 的对局有人分叉（100 局里约 2 局）。后来做到约万分之三。
手段：新英雄用机器人对打回归、体验服 / 抢先服先炸、分叉时上传整局录像和执行日志。

不同步率是生产指标。帧同步加英雄等于加分叉风险，没有录像回放就不敢扩内容。

## 作弊面

完整世界在每台手机的逻辑层。迷雾是表现层把模型藏起来。
改内存看全图，比 Dota 2「服务器根本没发坐标」容易。

服务器仍可做：输入频率、技能是否合法、Hash 对局。
闲的是「不广播每个小兵坐标」，不是「服务器当木头」。
若产品把视野当核心公平（杀手游戏、Dota 高地雾），这套天生弱一档。

## 大厅不要和同步搞混

匹配、关系链、排行走大厅，可以跨微信区、跨 Android / iOS（经 Adapter 桥到同一套 PvP）。
版本不一致不能匹配：十台逻辑二进制必须一样，他们不做多版本协议兼容。

问「王者是不是帧同步」时，只问 PvP 战斗。大厅永远是普通 C/S。

## 能抄什么、不能抄什么

能抄：手游、单位多、流量紧、技能要快写——乐观锁步 + 15Hz 是验证过的；
到帧就演 + 表现插值，比加输入延迟更跟手；UDP 冗余帧比再造一个 TCP 更听话；
不同步率配录像，否则锁步不敢迭代英雄。

不能抄：准星射击；以及「雾是唯一信息差」的玩法。
也不能把 15Hz 理解成画面只有 15 帧。
