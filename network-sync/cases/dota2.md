# Dota 2

主线：**Source 引擎的状态同步**。服务器模拟整张图，每隔一段时间把单位的位置和状态打成快照发给客户端。客户端在相邻快照之间插值，画面才平滑。

它不是 Warcraft 3、也不是 Dota 1 的帧同步。Dota 1 是一张 War3 地图，网上走输入，各端自己算。
Dota 2 换了 Valve 的 Source / Source 2，同步定律跟着换了：网上走的是**单位状态**，伤害在服务器算。

公开来源：Valve 工程师 Zoid 解释「为什么单位感觉慢半拍」
（快照频率、插值窗、以及为何不做 CS 那种预测）。
Source 2 实体上仍有 `m_nSimulationTick`、插值帧、`m_bPredictable` 等字段——
引擎里留着预测能力，不等于 Dota 玩法把它当 FPS 来开。

孙勋在 TGDC 把「dota」和星际放在帧同步一类，指的是 **Dota 1**。不要套到 Dota 2。

## 先记住三句话

1. 点地板、放技能，是给服务器下命令。服务器的英雄先动，你再看见。
2. 你看见的跑动，是两份快照之间的插值，不是你电脑在权威模拟。
3. 迷雾可以做到：雾外单位的坐标根本不在下行包里。这是锁步做不到的。

Zoid 的原话方向：Source 这套是为 CS / L4D / TF2 调的——你直接开着人，还要命中扫描。
Dota 2 是给战场上下命令，不是第一人称瞄准，所以不需要预测和滞后补偿才能瞄准。

## 一局里各台机器干什么

| 机器 | 干什么 |
| --- | --- |
| Dedicated Server（线上默认官方服） | 模拟所有单位、技能、兵线、野怪；定时打快照 |
| 你的客户端 | 把右键、技能键做成命令发出去；用快照插值画世界 |
| 别人的客户端 | 同样只画服务器给的状态，不负责算你的伤害 |

没有「十台电脑必须算出同一份世界」。只有一份世界，在服务器上。
你的客户端是带平滑的显示器，外加一个命令发送器。

## 点一下地板：逐步发生什么

Zoid 时期服务器把 `cl_updaterate` 锁在 **20Hz**，也就是每 50ms 一份快照。
默认 `cl_interp_ratio = 2`，插值窗大约 100ms（按 10Hz 显示，故意比发送慢一档来扛丢包）。

下面假设 ping 接近 0，只看插值本身。有 ping 时，每一步再叠加上行和下行各一程。

```text
时间    服务器                     你的客户端
0.00    发出快照 A                 只有 A，还不能插值，画面等着
0.05    发出快照 B                 开始在 A→B 之间插值
        此时你右键下令移动
        服务器立刻让英雄起步
0.10    发出快照 C                 插值窗仍可能罩着更早的快照
0.15    发出快照 D                 画面才完全跟上「已经在走」的那串快照
```

所以即使 ping 为 0，单位看上去也会晚几十毫秒才动。
Zoid 的估算：100ms 插值窗里，观感大约再加半窗（约 50ms），然后才是你的 RTT。
这不是策划加的「假延迟」，是「平滑」换来的滞后。

丢一个快照时，因为插值跨了约两份间隔，中间那一下被抹掉，单位不会瞬移。
这就是 ratio=2 的理由：用 100ms 的「活在稍微过去」换丢包不抖。

Zoid 当时在评估提高快照频率，把插值窗压到 50ms，让观感延迟再降一半。
后来的 Source 2 仍是快照 + netvar + 插值这一族。具体 Hz 可能调整过，模型没换成锁步。

## 为什么自己的英雄也不预测

在 CS 里，你按 W，本地立刻走路，否则准星无法瞄准。
在 Dota 里，你右键是「请英雄走到那里」。英雄要转身、走步、尊重碰撞和阻挡。
这段前摇本身就有几十到一百毫秒。插值藏在这段里，玩家归因为「英雄有转身」，而不是「枪卡住了」。

因此 Dota 2 **基本不做**「本地先把英雄拉到未来再等服务器」的 FPS 预测。
高 ping 时你会明确感到「点了才走」。那是 RTT + 插值叠在命令上，不是服务器故意怠工。

引擎字段里可以有 `m_bPredictable`。那是 Source 2 共用骨架。
玩法选择是：点地板移动仍以服务器起步为准，你等快照穿过插值窗。

## 技能和伤害在哪算

技能是否命中、控制是否生效、金钱经验，以服务器为准。
客户端可以先播前摇和特效，随后被快照纠正（技能被打断、目标已走）。
这比帧同步少「全场同一逻辑帧互打」，但 Dota 不靠格斗那种帧级对拼。

没有命中扫描准星，就不必为「我准星上的头」把全世界倒带。
滞后补偿不是这套玩法的刚需。

## 和 Dota 1 差在哪

| | Dota 1（War3 地图） | Dota 2 |
| --- | --- | --- |
| 引擎 | Warcraft 3 | Source / Source 2 |
| 网上走什么 | 所有人的输入 | 单位状态快照 |
| 世界在哪算 | 每个客户端各算一份 | 只在服务器算 |
| 掉线重连 | 补输入再快进，慢 | 拉当前快照，快 |
| 迷雾 | 本地其实有全图，界面藏起来 | 服务器可以不发雾外单位 |
| 主机 | 房间主机，偏 P2P | 官方 Dedicated Server |

玩法仍是 5v5 推塔。换引擎等于换同步定律：从 RTS 锁步迁到 Valve 快照。

**用重连判断。** 状态同步几乎立刻拿到「现在的世界」。
帧同步必须把缺的输入补齐并重跑。Dota 2 重连快，符合状态同步，不符合纯锁步。

## 为什么同是 MOBA 也可以走状态同步

端游带宽比 2015 年的手机宽。单位虽多，但 20Hz 快照、增量、以及迷雾裁剪，
并不是「每个小兵每帧全量坐标」。Valve 已有 QuakeWorld / Source 的 replicator，
不必为 MOBA 再造一套跨平台确定性逻辑。

命令式操作容忍 100ms 量级滞后。技能有前摇、弹道、转身。
玩家不要求「按下 WASD 身体立刻平移」。

服务器权威还直接养活：反作弊、观战、转播、暂停、单人重连。
迷雾是信息权：状态同步能让雾外坐标不存在于客户端内存。锁步做不到这一点。

## 这套的代价

带宽和服务器 CPU 随「相关单位数量」涨，不随「只传 10 个玩家的输入」那种无关。
兵线、野怪、眼、技能特效单位都要进快照或至少进相关性过滤。
这是和王者荣耀分道的主因之一：手机上同样 100 个单位，发状态会更疼。

自己不预测时，高延迟玩家的操作会「黏」。赛事和普通匹配都靠服务器选近的节点来压 RTT，
而不是靠本地预测把枪感做回去。

## 能抄什么、不能抄什么

能抄：命令式端游 MOBA 用 20Hz 量级快照 + 插值即可，不必上锁步；
用重连快慢判断别人在发状态还是发输入；迷雾当玩法时在服务器裁，不要只在客户端藏模型。

不能抄：把「MOBA = 帧同步」写成定律。Dota 2 和英雄联盟都是反例。
不能把 Source 里出现预测字段，解读成 Dota 2 在跑 CS 级预测。
