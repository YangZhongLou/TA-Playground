# 帧同步变种

帧同步只有一条硬定义：网上走输入，各端用同一份确定性 `F` 推出世界。
「变种」改的是节拍、拓扑、输入形态、缺包、落后追赶、重连，不是改成状态同步。

回滚仍传输入、仍跑 `F`，但执行时允许猜远程。它已离开纯帧同步，见 [rollback.md](rollback.md)。
本插件锁步分支默认是乐观节拍。四支内核互斥落地见 [../impl/lockstep-kinds.md](../impl/lockstep-kinds.md)。

## 先拆轴，再贴名字

口头上的「保守 / 乐观 / 桶同步」是节拍轴上的点。工程选型要把几根轴分开，否则会把拓扑和等待策略绑死。

| 轴 | 问什么 | 本插件现在站在哪 |
| --- | --- | --- |
| 节拍 | 谁决定打拍？缺人是停还是走？ | 服务器墙钟 15Hz，到点就广播 |
| 拓扑 | 输入经谁汇聚？ | 逻辑服务器 + 两客户端，不是 P2P |
| 缺输入 | 这一拍没新包怎么办？ | 沿用 `Latest` |
| 可靠 | 丢了怎么补？ | 每包带前 3 拍；不靠 TCP |
| 加入 | 新端从哪来？ | 每 75 拍检查点 + 尾巴输入 |
| 输入形态 | 每拍采样，还是稀疏命令？ | 每拍 `dx∈{-1,0,1}` |
| 落后 | 全场停、拉长回合，还是本地追帧？ | 缓冲里有连续拍就 `while Step` |
| 确定性 | 整数、锁编译器，还是买中间件？ | 整数 `FNsWorld` |
| 本地表现 | 按下后逻辑是否先演？ | 否。等 `S2CFrame` 再 `Step` |
| 服务器 | 只转发，还是也跑 `F`？ | 也跑 `F`，用来 checksum |

任意轴换一个值，**不一定**还叫帧同步。节拍（等齐 / 回合 / 乐观 / delay）、拓扑、缺包、输入形态、追帧、确定性，换了仍是锁步。
本地逻辑先演、或执行 `F` 时猜远程输入，已经出族：前者是预测，后者是回滚。

## 「乐观」绑了两件事

口语里两套策略都叫乐观，工程上不要混：

| 说法 | 实际做的事 | 本仓库叫什么 |
| --- | --- | --- |
| 王者 / 本插件锁步 | 墙钟到点就广播，逻辑仍等 `I(n)` | 乐观节拍 |
| GGPO | 执行 `F(n)` 时远程输入可以是猜的 | 回滚 |

前者不猜远程，只是不等齐。后者猜了才叫乐观执行。混用会把王者做成回滚，或把格斗做成等广播。

## 节拍变种

手感差一个数量级，几乎都出在这一轴。

### 保守锁步（囚徒）

汇聚点必须收齐所有人的 `I(n)` 才执行 `F(n)`。任一人迟到，全场停在 n。

操作延迟 ≈ 一程 RTT + 最慢那台的等待。局域网 RTS 能用。公网、手机容易全场卡死。

缺人出口：超时踢人、AI 托管。若改成「重复上一拍也开拍」，已经滑向乐观。

### 通信回合 + 固定提前量（帝国时代）

《Age of Empires》把渲染帧和通信回合切开。回合默认约 200ms。
本回合发出的指令，标到 **两回合之后** 才执行。回合 1000 点的兵，回合 1002 才走。

这样收包、确认、准备执行，可以和当前模拟重叠。指令延迟大约 400ms 量级；RTS 点选能接受，射击不能。

原始记录：[1500 Archers](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond)。

它仍是等齐：模拟只能跟最慢机器。不是「到点不管缺人」。

### 速度控制（自适应回合长度）

同一篇文章的 Speed Control：主机根据各端帧率和最大 ping，加权拉长或缩短通信回合。
变差时回合快速变长，好转后慢慢缩回去。玩家感到「整体变钝」，而不是周期性硬卡。

这是保守锁步的工业补丁，不是乐观锁步。全场仍同一世界、同一拍。

### 固定帧延迟（delay-based）

本地输入先在队列里躺 `d` 拍再进 `F`。常见 2～8 逻辑帧。格斗网战在回滚普及前用这个。

全员同一 `d`，没有「只有高 ping 的人回闪」。高延迟时所有人变钝。
和 AOE 两回合提前量是同一类：用固定迟钝换齐拍。差别是格斗逻辑 Hz 高（常 60），`d` 以帧计；RTS 以 200ms 回合计。

### 服务器定时 / 乐观锁步

节拍器在服务器。每 T 毫秒无论是否收齐都广播 `I(n)`。缺的人这一拍为空或沿用上一拍。

网差的人感到自己的操作晚进世界。网好的人不等他。当代手游帧同步主流，王者 66ms 即此。见 [honor-of-kings.md](../cases/honor-of-kings.md)。

本插件 `FNsLockstepServer::Tick` 走这一支：`Latest` 缺包沿用，墙钟到点就 `S2CFrame`。

王者试过「一有输入就立刻下发」（不再锁 15 包/秒）：手感几乎没涨，包量跟手速走，手机发烫，放弃。
也试过先攒几拍再演（delay-based）：卡。所以乐观节拍不等于「客户端先结算」。

### 表现层先动（已放弃的乐观）

逻辑仍等广播，模型先按本地输入动，广播到了再拉回。
这是状态同步的预测，不是帧同步。王者试过，角色发飘，放弃。
本插件锁步分支不要做这套。要零延迟本地打击，去 [rollback.md](rollback.md)。

### 回滚

执行 `F(n)` 时远程输入可以是猜的。猜错从存档重演。传的仍是输入。
互打公平靠磁带，不靠「等齐」。已不是囚徒，也不是王者那种「逻辑等广播」。

## 拓扑变种

| 拓扑 | 输入怎么汇 | 代价 |
| --- | --- | --- |
| P2P 全互联 | 每人发给其他人 | n² 包；NAT；无中心踢人 |
| 主机 Listen | 一人兼汇聚点 | 主机延迟优势；主机掉线散局 |
| 专用转发 | 服务器只编号、广播、补发 | CPU 低；反作弊弱 |
| 专用也跑 `F` | 转发 + Hash / 裁判 | 王者、本插件 |

帝国时代早期是 P2P。Definitive Edition 把包改走中继（NAT / 隐藏 IP），模拟仍在各端，中继没有权威世界。
拓扑换了，`F` 没换。不要把它写成王者那种「专用服跑 `F`」。

人数一多，P2P 先爆在对齐等待和包数，不在 `F` 本身。

## 缺输入变种

节拍到了，某槽没有新包：

| 策略 | 世界会怎样 | 谁难受 |
| --- | --- | --- |
| 停等 | 全场冻结 | 所有人 |
| 空输入 | 该玩家本拍不动 | 他本人「没按出去」 |
| 沿用上一拍 | 继续走上次方向 | 弱网会滑行 |
| AI 托管 | 服务器代填输入 | 本人暂时失去控制 |
| 踢人 | 槽位删除或补 AI | 房间人数变了，初态契约要改 |

本插件用沿用 `Latest`。两人局、输入是 `dx∈{-1,0,1}`，滑行可接受。
王者公开分享写的是「空输入或上一拍」，没有钉死。技能型 MOBA 若怕自动连点，用空，不要照抄本插件 `Latest`。

## 可靠传输变种

帧同步缺拍不能跳。可靠层必须在应用层：

| 机制 | 作用 | 本插件 |
| --- | --- | --- |
| 帧号 | 检测缺、重、乱序 | `ExecFrame` 禁止跳 |
| 冗余窗 | 每包带前 k 拍，抗短突发 | `RedundantFrames=3` |
| 周期 Join 尾巴 | 快照之后的 `Hist` 给晚加入 | 每 4 拍 `S2CJoinSnap`；快照每 75 拍 |
| 按号 NACK | 客户端点名缺哪几拍 | 未做（王者内存按号补发，本插件没有） |
| TCP | 队头阻塞 | 禁止 |

k 随丢包升高是王者的做法。本插件 k 写死为 3。
Join 包超 MTU 时 `NsSplitForMtu` 拆片，禁止 IP 分片。

## 加入与分叉变种

纯锁步没有当前世界，只有磁带。

| 做法 | 含义 |
| --- | --- |
| 从 0 快进 | 正确，二十分钟 15Hz 是上万拍 |
| 检查点 + 尾巴 | 每 M 秒存逻辑快照，重连吃最近一份再快进 |
| 分叉只记 Hash | 发现了但不能拉回 |
| 权威快照拉齐 | 所有人覆盖世界 |

本插件：75 拍检查点；checksum 迟到则忽略；Join 时 `Tick > ExecFrame` 跳世界。
检查点已经是「帧同步 + 少量状态」，不再是纯输入锁步。
包：[hybrid/checkpoint.md](hybrid/checkpoint.md)。
分叉拉齐是另一包：停拍、当前世界、强制回跳，见 [hybrid/resync.md](hybrid/resync.md)。

## 输入形态变种

节拍相同，线上字节可以完全不同。

| 形态 | 一拍里有什么 | 带宽怎么涨 | 缺包观感 |
| --- | --- | --- | --- |
| 每拍采样 | 摇杆 / 按键位图，空也占槽 | 人数 × Hz × 每槽大小 | 空输入则停；沿用则滑行 |
| 稀疏命令 | 「选中这些单位，去那里」 | 跟操作次数走，跟单位数无关 | 没有新命令则继续执行旧命令 |
| 事件卡牌 | 「这张牌放到格子 x」 | 极低 | 没有新事件则只走规则时钟 |

RTS / 星际 / 帝国时代走稀疏命令：点一次，单位自己沿路径走很多拍。
王者 / 本插件走每拍采样：摇杆每 66ms 都要进 `I(n)`，否则不知道你还按不按。
皇室战争一类走事件：输入不是 WASD，是出牌。逻辑仍每 tick 推 elixir、走兵。

同一套乐观节拍，采样空输入会让英雄站住，命令空输入会让兵继续跑。
品类选错这一轴，看起来像节拍选错。

## 落后：暂停、拉长、追帧

三件事不要收成同一个旋钮。

| 谁落后 | 房间怎么做 | 典型 |
| --- | --- | --- |
| 某端输入或 CPU 跟不上 | 全场停等 | 星际 2「某人拖慢了游戏」 |
| 某端 ping / 帧率变差 | 全场把通信回合拉长 | 帝国时代 Speed Control |
| 本机 `ExecFrame` 落后已收包 | 跳过表现，连续 `Step` | 手游乐观锁步的追帧 |
| 断线太久 | 踢人或 AI 托管 | 王者、SC2 超时踢 |

追帧是**本机**行为：包积压时逻辑连跑多拍，画面快进。
速度控制是**全场**行为：回合变长，所有人一起钝。
暂停等齐也是全场，但顿一下而不是变钝。

乐观节拍仍然要追帧。服务器 15Hz 往前走，你卡了 200ms，回来要连跑 3 拍才能对齐广播。
本插件客户端 `while (Buf.Find(ExecFrame)) Step` 就是追帧，没有每渲染帧上限。

重连追帧更重：检查点之后的尾巴一次快进完。王者卡在这里，不是卡在 15Hz 本身。

## 确定性怎么买

锁步成立的前提是 `F` 位相等。买法有三档，和节拍无关。

| 买法 | 做法 | 代价 |
| --- | --- | --- |
| 整数 / 定点 | 逻辑不用 IEEE 754 | 手写物理、路径 |
| 锁二进制 | 同编译器、`/fp:strict`、关多余 SIMD | 跨 ARM/x86、跨商店包会破 |
| 确定性中间件 | Photon Quantum ECS、自研定点引擎 | 逻辑离开 UE/Unity 默认世界 |

星际、王者、本插件走整数/定点。部分 RTS 重制版走锁二进制浮点。
中间件解决的是 `F`，不自动选定节拍：Quantum 默认是预测回滚，见下一节。

## 软锁步与 Photon Quantum

Quantum 官方把「所有人等齐再 Tick」叫做过时的 lockstep，默认是 **predict/rollback**：本地先演，服务器签发输入流，猜错再倒。
它可以打开 `LockstepSimulation`：不做回滚，并建议 `InputDelayMin ≥ 10`。那是 delay-based，不是王者那种到点广播。

他们还推荐一种 **soft lockstep**：输入偏移够大，回滚很少触发，必要时仍能倒。
这是「延迟锁步 + 回滚逃生门」，不是保守囚徒。

本仓库不要把 Quantum 写进帧同步代表名单。
执行规则默认已离开纯锁步，进 [rollback.md](rollback.md)。不要按王者 15Hz 去抄 Quantum。

## 工业产品钉在哪几轴

| 产品 | 节拍 | 输入 | 拓扑 | 落后 |
| --- | --- | --- | --- | --- |
| 帝国时代 | 通信回合 + 两回合提前 + Speed Control | 稀疏命令 | 早期 P2P，后作经中心 | 回合拉长 |
| 星际 1 / 魔兽 3 / Dota 1 | 等齐 | 稀疏命令 | P2P | 掉线散局 |
| 星际 2 | 等齐 + 命令缓冲（社区常报 ~200ms，非暴雪白皮书） | 稀疏命令 | 对战经中继一类 | 全场顿，超时踢 |
| 王者荣耀 | 乐观 15Hz | 每拍摇杆+技能 | 专用服跑 `F` 做 Hash | 自己迟；重连检查点追帧 |
| 皇室战争一类 | 确定性 tick | 出牌事件 | 服务器 | 操作低频，追帧轻 |
| 本插件 | 乐观 15Hz | 每拍 `dx` | 逻辑服务器 | `while Step` 追帧 |
| Quantum 默认 | 回滚 | 每 tick 输入 | Photon 签发 | 不等慢端 |
| Quantum `LockstepSimulation` | delay-based | 每 tick 输入 | 同上 | 固定偏移 |

帝国时代与星际 2 同属「命令 + 固定提前量 + 等齐」。差别在落后策略：前者平滑拉长回合，后者更容易整局停一下。
王者把等齐拆掉，输入改成每拍采样。这是手游 MOBA 相对 RTS 的真正跳跃，不是「也叫帧同步」四个字。

## 对照表

| 变种 | 族内 | 等待 | 本地逻辑先演 | 延迟量级 | 典型 |
| --- | --- | --- | --- | --- | --- |
| 保守等齐 | 是 | 等所有人 | 否 | 最慢端 RTT | 早期局域网 RTS |
| AOE 回合 + 两回合提前 | 是 | 等齐，回合可拉长 | 否 | ~400ms 指令延迟 | 帝国时代 |
| 固定帧延迟 | 是 | 等 d 拍 | 否 | `d ×` 逻辑步 | 旧格斗网战 |
| 乐观服务器定时 | 是 | 不等 | 否 | `RTT + T/2` | 王者、本插件 |
| 软锁步 | 否（回滚逃生门） | 大偏移，偶发回滚 | 多数时候像 delay | 接近 `d` 拍 | Quantum 推荐档 |
| 表现先动 | 否 | 逻辑仍等 | 表现是 | 看起来低，会拉回 | 王者放弃 |
| 回滚 / Quantum 默认 | 否 | 不等 | 是，错了再倒 | 本地 0～1 拍 | GGPO、Quantum |

## 品类怎么落到变种

| 品类 | 该用哪一支 | 不要用哪一支 |
| --- | --- | --- |
| RTS 点选 | 通信回合或等齐 + 速度控制 | 乐观**采样**空输入（兵会停走无常；稀疏命令下空输入仍继续走） |
| 手游 MOBA | 乐观 10～20Hz + 冗余 + 检查点 | 保守等齐；客户端先结算技能 |
| 自走棋 / 塔防 | 乐观或回合，操作低频 | 回滚（没有按键即打击） |
| 实时卡牌 | 事件命令 + 确定性 tick | 每拍摇杆；回滚 |
| 格斗 | 回滚或 Quantum 默认 | delay-based 已过时；乐观空输入会吞招 |
| 射击 | 不要帧同步 | — |

PC MOBA（Dota 2、英雄联盟）是状态同步。Dota 1 / 星际是帧同步。不要把 MOBA 当成帧同步同义词。

## 和本插件的距离

已实现：`Optimistic`（`NsLockstep.*`）；`Conservative`（`NsLockstepWait.*`，收齐再 `F`，超时填空）。

未实现的两支内核各有独立规格，**另开类型和泵**，不要改 `NsLockstep.cpp`：

| Kind | 规格 |
| --- | --- |
| CommTurn | [../impl/lockstep-comm-turn.md](../impl/lockstep-comm-turn.md) |
| DelayBased | [../impl/lockstep-delay.md](../impl/lockstep-delay.md) |

入口与硬规则：[../impl/lockstep-kinds.md](../impl/lockstep-kinds.md)。

不必并进乐观类的旋钮：自适应 `LogicDtMs`、P2P、按号 NACK、分叉后权威拉齐、稀疏命令载荷、追帧限流。

不要把回滚并进 `ENsScheme::Lockstep`。四套主方案互斥；四支锁步内核也互斥。

## 失败模式（按变种）

| 现象 | 更可能是哪一支 |
| --- | --- |
| 全场周期性卡 | 仍在等齐，或冗余不够在停等 |
| 只有自己迟 | 乐观：你的上行丢了，别人仍在走 |
| 全员一起变钝 | 速度控制把回合拉长了 |
| 全场停一下，提示某人拖慢 | 等齐 + 暂停，不是乐观 |
| 自己画面突然快进 | 追帧：本机连跑积压拍 |
| 点了要等半秒才动 | AOE / SC2 命令提前量，或 delay `d` 太大 |
| 角色发飘 | 在锁步里做了预测拉扯 |
| 买了「锁步中间件」却在回闪 | Quantum 默认回滚，不是王者节拍 |
| 两个世界 | 确定性破了，与节拍变种无关 |
