# 状态同步 / 快照复制

服务器（或主机）持有**一份**权威世界。网上走的是状态：某时刻谁在哪、血量多少、技能处于哪一态。
客户端用快照插值画出别人，用预测补自己的手感。伤害、击杀、拾取以服务器为准。

QuakeWorld / Quake 3 / Source 把这套写成工业标准。
守望先锋、Dota 2、Valorant、Fortnite、UE 默认复制，都是这一族的不同旋钮。

案例：[overwatch.md](../cases/overwatch.md)、[dota2.md](../cases/dota2.md)。
对象级落地见 [replication.md](replication.md)。预测、插值、补偿见 [techniques.md](../techniques.md)。

## 这一拍同步了什么

同步的是 `WorldState(t)` 的子集，不是 `Input(n)` 全集。
客户端不必能独立把世界推到下一秒；缺了服务器，本地会停或猜错。

因此带宽跟「每条连接关心的实体数 × 每实体字节 × 发送频率」走。
单位一多就要 AOI、休眠、降频、量化。RTS 小兵精确同步走这里会先把带宽打满。

权威在服务器。客户端改本地血量，下一份快照会把它改回去——前提是伤害公式也在服务器跑。

## 三种频率不要混

| 名字 | 谁身上 | 含义 |
| --- | --- | --- |
| 模拟 Tick | 服务器 | 物理和判定每秒走几次（30 / 60 / 128） |
| 发送频率 / updaterate | 每条连接、每对象可变 | 快照每秒发几次（10 / 20 / 64） |
| 命令频率 / cmdrate | 客户端上行 | 输入每秒送几次 |
| 插值窗 | 客户端显示 | 故意落后多少毫秒再画远程物体 |

Valorant / CS 把 Tick 拉高，因为命中扫描吃时间分辨率。
Dota 2 在 Zoid 的说明里快照锁 20Hz，插值窗约 100ms，因为点地板不需要准星。
MMO 可以 5～10Hz 发位置，靠插值圆场。

发送可以低于模拟：服务器 64Hz 模拟，对某个远处门 2Hz 发送。这是对象复制的日常。

## 服务器循环

1. 收客户端输入（带序号、时间戳）。非法输入丢弃或钳制。
2. 用固定 Tick 推权威世界。移动、技能、物理、伤害都在这里。
3. 对每个连接：按相关性挑实体，按频率和预算打包。
4. 能增量就相对「该连接最后确认的快照」做差；否则发全量。
5. 发出去。不可靠通道走姿态；可靠通道走击杀、背包、阶段切换。

客户端循环见下一节。两边的 Tick 可以对齐（预测好做），也可以不对齐（要额外换算时间）。

## 快照里有什么

一份快照至少要让客户端知道「这是服务器的哪一拍」以及「哪些对象怎么了」。

| 块 | 内容 |
| --- | --- |
| 头 | 服务器 Tick / 时间戳、这是相对哪份基快照做的差 |
| 创建 | 新出现的实体：类型、初始字段、NetID |
| 删除 | 消失的 NetID |
| 更新 | 还活着的实体的脏字段 |
| 事件（可选） | 不便放进「当前值」的一次性事实 |

**全量快照**：该连接此刻关心的全部字段。首次进入、重连、基快照丢失时用。贵。
**增量快照**：只发相对基快照的差。稳态时便宜。基快照必须是**客户端 ACK 过的那份**，
不能是「服务器上次发出的那份」——发出去不等于对方收到。

ACK 丢了：服务器应能换更老的基，或放弃增量发全量。基选错是「假增量」，客户端会把世界解错。

实体要有稳定 NetID。创建和删除必须能在丢包后从后续快照重建。不要用「可靠 RPC 生成、不可靠快照更新」这种容易漏的组合当唯一生成路径。

## 客户端怎么显示远程物体

远程物体不要画「最新一份快照」。最新一份的下一包还没到，物体会跳。

标准做法（Source 插值）：

1. 缓冲里至少有快照 A、B，时间戳 tA < tB。
2. 显示时刻 `tShow = tNow - interpDelay`。interpDelay 常取 `ratio / updaterate`（ratio=2 时约两拍）。
3. 若 tA ≤ tShow ≤ tB，按 (tShow−tA)/(tB−tA) 在 A、B 的位姿之间插值。
4. tShow 比最新快照还新：缓冲耗尽，只能外推（按最后速度往前估），或卡住最后姿态。
5. 外推错了（对方急停），下一份快照会把人拽回来，即回弹。

interpDelay 过小：经常外推，瞬移多。过大：所有敌人活在过去，近身互打对空气。
射击游戏因此把「我看见的敌人」和「服务器判定用的敌人」分成两套时间，见滞后补偿。

本地玩家不要走这套。否则自己会感到延迟。本地走预测。

## 自己角色：预测与和解

1. 输入立刻作用于本地模拟（移动、开火动画、技能前摇）。
2. 输入带序号发给服务器，本地存进「未确认队列」。
3. 服务器结果带着「已处理到序号 x」回来。
4. 本地把状态倒回 x 对应的服务器权威，再把 x 之后的输入重放一遍，追到「现在」。
5. 重放结果与当前显示差在阈值内：平滑。超出：硬纠正（橡皮筋）。

重放必须用**历史世界**做碰撞，不能用「现在已经变了的墙」。动画、冷却若参与预测，也要进存档。
预测范围是设计选择：Dota 2 几乎只预测到「命令已发出」；
守望先锋默认预测移动、武器、技能甚至火箭。见两篇案例。

预测的是自己拥有的对象。预测别人 = 猜别人的输入，那是回滚方案的正式机制，不是状态同步的默认。

## 命中：滞后补偿

你开火时，准星上的人是 tShow 时刻的插值，比服务器「现在」旧一个 interpDelay，再加一程延迟。
服务器若用「此刻」的人判定，你会打空已经套住的模型。

服务器保留一小段历史姿态（大约 RTT + 插值窗）。开火时把受害者倒带到射击者当时的画面时刻，再打射线。
这保护射击者的所见即所得，牺牲被射者「我已经进掩体」。

窗口必须封顶（守望先锋公开量级约 220ms 以上关掉回绕改外推）。
不封顶等于允许高 ping 打过去的人。封顶后高延迟玩家命中变差，这是刻意的。

不是全图都倒带。先用粗包围体剔除，再精确回绕。Valve 论文是祖先，链接在 [references.md](../references.md)。

## 丢包时什么会自愈、什么不会

姿态走不可靠：丢了，下一快照仍会把人放到对的地方。这是状态同步相对帧同步的最大传输优势。

一次性事实（开门成功、扣了一件装备、进入下一阶段）丢了不会「下一快照自动有」——
除非你把它做成属性的当前值（门是开还是关）。能做成当前值的，优先做成属性。
只能做成「发生过」的，走可靠 RPC / 可靠事件，并接受队头阻塞。

用可靠 RPC 每帧发位置是误用：丢包时位置卡在队头，延迟尖刺。

## 带宽怎么砍

按收益顺序：

1. **不发**：AOI、休眠、雾外不发、距离裁。最大头，兼反透视。
2. **少发**：降频率、位移阈值、优先级预算（先发交战中的敌人）。
3. **发得小**：量化（位置 16bit 定点 + 世界范围）、旋转压缩、位域、相对 ACK 基的增量。

每条连接设每秒字节顶。超了不要平均卡所有对象，按优先级丢低价值更新。

复杂度：无 AOI 时约 O(实体 × 连接)。百人同场必须网格 / Replication Graph / Iris Filter。

## 时钟

快照带服务器时间戳。客户端估计服务器时间：`tServer ≈ tPacket + RTT/2`，指数平滑，禁止跳变。
插值、补偿、预测重放都认这套时间。

不要用客户端墙钟当「服务器第几毫秒」。也不要把锁步的帧号和这套时间戳当成同一个「现在」
去写同一份 Transform。

## 反作弊

| 风险 | 协议能做的 |
| --- | --- |
| 改位置 / 伤害 | 服务器跑移动和公式；客户端结果只是预测 |
| 透视 | 不发不可见实体；遮挡裁剪 |
| 包注入 / 改别人 | 所有权、序号、签名 |
| 自瞄 | 协议消灭不了，靠检测与反作弊服务 |

「不发看不见的」必须从第一天进设计。事后加 AOI 会翻表现和玩法（突然出现的敌人）。

## 失败模式

| 现象 | 常见原因 |
| --- | --- |
| 别人走路一顿一顿 | 插值窗小于丢包间隙；或发送过稀 |
| 自己橡皮筋 | 预测与服务器移动不一致；重放用了当前碰撞 |
| 打到墙后 | 滞后补偿窗口过大，或客户端插值与回绕时间没对齐 |
| 门开了又关上 | 门用了不可靠 RPC 而不是复制的开关属性 |
| 重连很快但雾外闪一下 | 快照没按视野裁，或先全量后过滤 |
| 百人时服务器 CPU 打满 | 每个连接穷举所有 Actor 做相关性 |

## 变体

| 变体 | 要点 |
| --- | --- |
| 经典快照（Source） | 世界切片 + 插值 + 可选预测 |
| 对象复制（UE / NGO） | 按 Actor 切，属性 + RPC，见 replication |
| 客户端权威 | 拥有者说了算，服务器转发；休闲、易作弊 |
| 共享权威 | 各拥有各的对象；冲突要额外规则 |
| 确定性快照（Netcode for Entities） | 状态仍下行，但模拟可预测重演，接近锁步/回滚混合 |

## 适用边界

适合：射击、载具、物理、开放世界、随时加入、观战、服务器必须当裁判。
不适合：上千精确小兵的 RTS（发不起）；帧级互打的格斗（插值不是同一帧碰撞框）。

代表：Source 系、CS / Valorant、Fortnite、守望先锋、Dota 2、英雄联盟、大多数 UE 联机。
