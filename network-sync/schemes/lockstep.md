# 帧同步 / 确定性锁步

网上只传**输入**。每个模拟端（或「服务器 + 所有客户端」）从同一初态出发，按同一帧号执行同一串输入。逻辑确定，则世界必然相同。

国内称帧同步。欧美称 Deterministic Lockstep。它是输入同步，不是状态同步。

落地案例见 [honor-of-kings.md](../cases/honor-of-kings.md)。和回滚的边界见 [rollback.md](rollback.md)。

## 这一拍到底同步了什么

同步的是「第 n 拍，玩家 0..k 各自的输入」。不同步「小兵 17 的坐标」。小兵坐标由各端用同一套逻辑推出来。

因此带宽跟**人数 × 输入结构**走，跟场上单位数几乎无关。这是 RTS、自走棋、手游 MOBA 选它的理由。

前提有三条，缺一条就会分叉：

1. 初态相同（随机种子、关卡、英雄选择、版本二进制）。
2. 每一拍的输入集合相同，且按同一帧号执行。
3. 从输入到世界的函数 F 确定：`S(n+1) = F(S(n), I(n))`。

## 一拍的标准循环

给每一逻辑拍一个单调帧号 `n`。渲染帧号与它无关。

1. 各端把本地操作写成输入（按键位、摇杆量化、指令 ID）。带上 `n` 或「尚未确认的最新操作」。
2. 汇聚点（专用服务器或主机）决定：**这一拍的 I(n) 是什么**。
3. 把 I(n) 可靠、有序地发给所有模拟端。缺拍不能跳。
4. 各端执行 `S := F(S, I(n))`，`n := n+1`。
5. 每隔若干拍，把关键状态做成 Hash / checksum，对不上就进入不同步流程。

表现层在 S 上插值、播动画。表现不准许写回 S。

## 输入长什么样

输入必须小、可量化、可回放。

| 字段 | 作用 |
| --- | --- |
| 帧号 / 序列号 | 有序执行、去重、补发 |
| 玩家 ID | 这一拍里谁的操作 |
| 离散操作 | 技能槽、购买、攻击指令，用枚举 |
| 连续操作 | 摇杆、瞄准角，量化成整数（如 8～16 bit） |
| 空输入 | 本拍没操作，仍要占一个槽，保证 F 的输入齐全 |

RTS 常发「选中单位 + 命令 + 目标」，而不是每帧 WASD。MOBA 常发摇杆方向 + 技能按钮。
格斗的 delay-based 锁步发的是按键位图。同一族，载荷不同。

连续量一旦用 float 原样过网，各端量化误差会在 F 里放大。逻辑层从入口就应是整数。

## 三种节拍方式

「帧同步」不是一种等待策略。节拍怎么打，手感差一个数量级。
完整变种见 [lockstep-variants.md](lockstep-variants.md)。四支可独立落地的内核见 [../impl/lockstep-kinds.md](../impl/lockstep-kinds.md)。本节只钉三种最常对上号的。

### 保守锁步（囚徒）

汇聚点必须收齐所有人的 I(n) 才广播。任一人迟到，全场停在 n。
手感 ≈ 最慢端 RTT + 对齐等待。局域网 RTS 能用。公网、手机容易全场卡死。

缺人时的出口只有：超时踢人、AI 托管、或用「重复上一拍输入」顶上（已经开始掺乐观）。

### 固定帧延迟（delay-based）

本地输入先在队列里躺 `d` 拍（常见 2～8 帧）再进 F。
用固定迟钝换齐拍，减少「这一拍还缺人」。格斗网战在回滚普及前用这个。
高延迟时所有人变钝，没有「只有高 ping 的人回闪」这种不对称，但大家都慢。

### 服务器定时 / 乐观锁步

节拍器在服务器。每 T 毫秒（王者是 66ms）无论是否收齐，都广播 I(n)。
缺的人这一拍为空或沿用上一拍。网差的人感到自己的操作晚进世界，网好的人不等他。

这是当代手游帧同步的主流。它仍是输入同步：各端仍跑 F。只是不再当囚徒。
代价：网差的人在别人眼里「反应慢」，公平性靠匹配和超时托管，不靠全场等待。

帝国时代不是「介于乐观与保守之间的桶」。它仍等齐，只是把等待收进约 200ms 的通信回合，指令再推迟两回合执行。见 [lockstep-variants.md](lockstep-variants.md) 与 [references.md](../references.md) 的 1500 Archers。

## 传输必须可靠有序

I(n) 丢了或乱序，F 就不能往前。这和状态同步相反：状态丢了，下一份快照还能纠正。

因此帧同步几乎都在 UDP 上自建：

| 机制 | 作用 |
| --- | --- |
| 帧号 | 检测缺拍、重复、乱序 |
| 应用层补发 | 按号从服务器内存取出 I(n) 再发 |
| 冗余 | 每个包带上前 k 拍（王者默认 k=3，丢包升则加大） |
| 分包 | 超过安全 MTU 在应用层拆成多个 UDP；禁止 IP 分片（丢一片则整报作废） |
| 过时输入丢弃 | 同一玩家更新的操作覆盖旧的未打包输入 |

不要用 TCP 的重传和慢启动扛这一层。外网丢包时队头阻塞会让整局卡住。
王者先上 TCP 再改 UDP，原因就是重连和抖动。见 [honor-of-kings.md](../cases/honor-of-kings.md)。

## 确定性细则

F 一旦在某台机器上走出不同的位，之后每一拍都会在错误世界上继续走，而且越走越远。
没有「下一包纠正坐标」这种自愈。

| 破坏源 | 必须怎么做 |
| --- | --- |
| IEEE 754 跨 CPU / 编译器 | 逻辑用定点（Q 格式）或锁编译器、锁指令集、关多余 SIMD |
| fused multiply-add、denormal | 同一套编译开关；或根本不用 float |
| `hashmap` / `dict` 遍历 | 逻辑只用数组或有序 map |
| 随机 | 种子进同步；PRNG 按确定顺序取；禁止 `rand()` 读墙钟 |
| 物理引擎 | 自研确定性物理，或逻辑不用 PhysX/Chaos |
| 动画通知驱动伤害 | 禁止。动画在表现层；伤害只认逻辑拍 |
| 多线程 | 逻辑单线程，或并行后按 ID 归约，禁止数据竞争 |
| 墙钟 / `deltaTime` | 逻辑只认固定步长。表现层才用渲染 delta |
| 协程 / 引擎消息顺序 | 逻辑有唯一 tick 入口，自上而下，顺序写死 |
| 未初始化内存 | 初态必须填满，否则各端垃圾不同 |

手游还要过 ARM 与 x86、IL2CPP 与不同厂商 NDK。商业项目通常把战斗逻辑做成独立模块：
定点 ECS、Lua 整数、或 Photon Quantum 这类确定性引擎。Unity / UE 的默认物理不要进 F。

## 逻辑与表现必须切开

| 层 | 频率 | 允许 |
| --- | --- | --- |
| 逻辑 | 固定，如 15 / 20 / 30 Hz | 伤害、碰撞、AI、CD、随机 |
| 表现 | 渲染帧，30 / 60 / 120 | 插值、动画、特效、镜头 |

逻辑 15Hz 不等于画面 15 帧。表现按逻辑位置和速度插值。
表现写回逻辑（用动画事件扣血、用渲染碰撞做命中）是不同步第一名。

## 不同步：发现、复现、收场

**发现。** 每隔 N 拍对关键字段做 Hash：单位位置、血量、随机计数器、对象个数。
各端（或服务器那一份）比对。对不上就标记分叉者。

**复现。** 整局输入本来就能录像。再加执行日志（每拍 Hash、关键事件）。
用同一份输入在工具里单端重跑，二分到第一次 Hash 变化的那一拍、那一行逻辑。

**收场。** 纯锁步没有「服务器改一个坐标」。分叉后只能：踢分叉者、整局作废、
或掺一份权威快照把所有人拉回（破坏纯度，但能救命）。
停拍拉齐单独成包：[hybrid/resync.md](hybrid/resync.md)。停拍、发当前世界、强制回跳，不要写进乐观打拍循环，也不要复用只向前的 `ApplyJoin`。
王者上线约 2% 对局分叉，后来到约万分之三，靠的是机器人回归和录像，不是靠协议自己愈合。

## 重连、观战、中途加入

纯锁步的新端没有「当前世界」。它只有输入磁带。必须从 S(0) 快进到当前 n。
二十分钟、15Hz 是上万拍，要压缩执行（跳表现、合并可跳过的纯计算）。

商业实现会在服务器存检查点：每 M 秒一份逻辑快照 + 之后的输入。
重连吃最近检查点再快进尾巴。这已经是「帧同步 + 少量状态」。
检查点单独成包：[hybrid/checkpoint.md](hybrid/checkpoint.md)。不要和停拍拉齐、锁步加门写进同一个类。

观战同理：播已确认的输入流。不要让观战端参与 I(n) 的汇聚。

版本必须一致。逻辑二进制不同就不能进同一房间。王者因此不做多版本协议兼容。

## 服务器还要不要模拟

可以只做转发：收输入、打拍、补发、Hash 抽检。省 CPU。
也可以再跑一份完整 F，用于：反作弊、裁判、观战权威、结算。

即使服务器跑 F，下行仍应是输入而不是全量坐标——否则你已经在付状态同步的带宽，
却仍要付确定性的税。校验用 Hash 即可，不必每拍广播世界。

## 作弊面

每台客户端逻辑层都有完整世界。战争迷雾若只藏模型，改内存就能透视。

| 风险 | 能做的 |
| --- | --- |
| 透视 / 全图 | 敏感数据不要进表现进程；服务器校验异常操作；不能从协议上消灭 |
| 改伤害 | 服务器跑一份 F 对 Hash；或关键结算只信服务器（开始掺状态） |
| 加速 | 不认客户端 delta；超时输入丢弃 |
| 脚本挂 | 检测操作频率、技能 CD、移动合法性 |
| 重连偷雾外 | 检查点快照按视野裁，不要把全图镜像发给重连者 |

「帧同步服务器很闲所以不管」是误读。闲的是不广播小兵坐标。

## 变体对照

细则按轴拆开，见 [lockstep-variants.md](lockstep-variants.md)。节拍怎么打，手感差一个数量级。

| 变体 | 等待 | 本地是否先演 | 典型 |
| --- | --- | --- | --- |
| 保守锁步 | 等齐 | 否 | 早期 RTS、局域网 |
| 桶 / 通信回合 | 等一个时间桶，可拉长 | 否 | 帝国时代 |
| 固定帧延迟 | 等 d 拍 | 否，但本地有固定迟 | 旧格斗网战 |
| 乐观 / 服务器定时 | 不等 | 否（逻辑等广播） | 王者荣耀、本插件 |
| 回滚 | 不等 | 是，错了再倒 | GGPO |

最后一行已经离开「纯帧同步」进入 [rollback.md](rollback.md)。
本插件默认锁步是乐观节拍 + 冗余 3 拍 + 检查点。等齐是另一支 Kind：`NsLockstepWait.*`。

## 失败模式

| 现象 | 常见原因 |
| --- | --- |
| 全场周期性卡一下 | 仍在等齐；或冗余不够，缺拍才补 |
| 只有自己迟 | 乐观锁步下你的上行丢了，别人仍在走 |
| 十个人渐渐打出两个世界 | 浮点、无序遍历、本地逻辑、版本不一致 |
| 重连要转圈很久 | 快进无检查点，或检查点太稀 |
| 手机发烫 | 把每一下操作都立即广播，包率跟手速走 |
| 角色发飘 | 混进了 C/S 预测拉扯，和锁步抢同一 Transform |

## 适用边界

适合：单位很多、输入很小、能接受技能前摇式延迟、能把逻辑写成定点模块。
不适合：准星射击、非确定物理、随时进出的 MMO、把迷雾当核心公平且无法忍受本地全图。

代表：星际争霸、帝国时代、王者荣耀、多数日式手游对战。
Photon Quantum 默认是预测回滚，不是王者那种乐观节拍，见 [lockstep-variants.md](lockstep-variants.md)。
PC MOBA（Dota 2、英雄联盟）走状态同步，见 [dota2.md](../cases/dota2.md)。
