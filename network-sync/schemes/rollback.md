# 回滚同步

本地**不等**远程输入。每一模拟帧：自己的按键立刻进逻辑；别人的按键先猜（通常复制上一帧）；把这一帧状态存下来；继续往前演。
真输入迟到后，若与猜测不同：倒回分歧帧，换上真输入，一路重演到当前。

网上走的仍是**输入**，不是对方坐标。对方人在哪，是你本地用他的输入重演出来的。
所以它是乐观锁步，不是状态同步。GGPO 是这套的开源参考实现。格斗游戏线上主流。

不要和守望先锋的「预测和解」混名。那边真值是服务器快照，只回退你自己的英雄。
这边真值是对端真实输入，回退整份对打逻辑。对照见 [overwatch.md](../cases/overwatch.md)。

## 这一帧同步了什么

同步的是「玩家 i 在逻辑帧 n 的输入」。各端都跑同一份确定性 F。
和保守锁步的差别只有一句：**执行 F(n) 时，远程的 I_remote(n) 可以还是猜的。**

猜对了：玩家感到零输入延迟。猜错了：画面上的人会倒回去再走一遍。
工程的核心是让猜错少、倒回去快、倒回去的痕迹被表现层藏住。

## 帧上的三种时间

| 名字 | 含义 |
| --- | --- |
| 确认帧 | 所有人的真实输入都已到达，F 从这一帧起不可再改 |
| 预测帧 | 当前正在显示的帧；远程输入可能仍是猜的 |
| 回滚深度 | 预测帧 − 分歧帧。一次最多重跑这么多拍 |

窗口是环形的：保存最近 R 帧的状态和输入（R 常见 8～16）。
真输入比 R 还晚到：不能无限猜，要减速等待（退回锁步）或判掉线。

## 一帧的循环（GGPO 形态）

对逻辑帧 n（通常 60Hz，步长 16.67ms）：

1. 采集本地输入 I_local(n)。立刻可用。可再加 0～3 帧输入延迟（见下）。
2. 发送 I_local(n) 给对端（可靠、带帧号；常冗余最近几帧）。
3. 若 I_remote(n) 已到，用真的；否则用预测，常见策略是复制 I_remote(n−1)。
4. 把 S(n) 存档（整份 memcpy 或增量检查点）。
5. `S(n+1) = F(S(n), I_local(n), I_remote(n))`。渲染用 S(n+1) 的表现投影。
6. 当某个更早的 m 收到与预测不同的真输入：加载 S(m)，填真输入，从 m 重演到当前。
7. 表现层处理 6：动画过渡、命中特效等确认后再播，避免「打中又收回」。

预测远程输入最简单的启发式是「继续按住刚才的键」。格斗里走路、蓄力经常连续多帧相同，所以猜对率高。
变招、反制、突然停手是猜错的高发区——也正是回滚最明显的时候。

## 输入延迟旋钮

即使做了回滚，仍可把本地输入故意晚 d 帧再进 F（d=0,1,2,3）。

| d | 效果 |
| --- | --- |
| 0 | 最跟手；回滚次数最多；高 RTT 时闪得凶 |
| 1～2 | 常见折中；许多家用 Wi-Fi 局的默认 |
| 更大 | 接近 delay-based 锁步；稳，但按键变钝 |

两端 RTT 不对称时，只让高 ping 的人多回滚会感觉「他在瞬移、我在正常打」。
常见补法：按双方 RTT 加**相同的**输入延迟，让回滚次数接近。公平优先于「我这边绝对零延迟」。

再加一条：帧优势（frame advantage）。若一端持续更早执行预测帧，时间同步会让快的一端稍慢、慢的一端稍快，把确认点对齐。
GGPO 带这一套。不要只抄存档重演，漏掉时间同步，否则一边永远在深回滚。

## 存档必须满足的数字

回滚窗口内，每帧都要能存、能读、能重跑。

| 约束 | 量级直觉 |
| --- | --- |
| 状态体积 | 只含逻辑：位置、速度、输入状态机、命中框、随机计数器。特效、UI、音效不要进来 |
| 存档耗时 | 亚毫秒。整份 memcpy 最简单；太大再做增量 |
| 重演耗时 | 最坏重跑 R 帧仍要挤在一帧渲染预算里。单帧 F 必须很轻 |
| 副作用 | 预测帧里播的声音、振动、命中停顿必须能撤销或延后到确认帧 |

逻辑与表现分离在这里是硬条件，比帧同步更硬：帧同步可以等确认再播特效；
回滚会先播「可能发生的命中」，确认失败就要收回。格斗本来就有「顿帧等确认」的管线，和这套合得上。

人数上升：每人一份预测输入，错误组合变多，存档变大。2～4 人舒适，8 人要克制，再往上通常不该当主线。

## 确定性

重演段的 F 必须确定，否则倒回去会走出另一个世界，比「不回滚」更糟。
要求与 [lockstep.md](lockstep.md) 的确定性表相同：定点、有序遍历、种子 PRNG、禁止动画驱动逻辑。

额外一条：存档必须包含 PRNG 状态和所有会改变 F 的隐式状态（剩余无敌帧、连段计数、输入缓冲）。
漏一项，重演必分叉。

## 传输

输入包小。2 人 60Hz 按键位图，带宽通常不是瓶颈。难点是迟到和乱序。

- 带帧号，乱序也能填进窗口对应槽。
- 冗余最近几帧，丢包由下一包补上，不必等单独重传再演（窗口内）。
- 超出窗口：停下来等，或按锁步方式减速，或断开。

P2P 常见（格斗房间）。也可以经 Relay 只转发输入，不模拟。
没有 Dedicated Server 当「世界真值」并不妨碍回滚——真值是输入磁带。
若还要反作弊，可以另加服务器跑一份确认模拟，那是叠加，不是回滚本身。

## 观战、重连、录像

观战只播确认帧，不要预测，否则观众看到的回闪和选手不同步。
重连：发一份逻辑快照 + 之后的输入（和帧同步相同的结构税）。
录像：存输入磁带即可，和锁步一样能精确重放。这是相对状态同步录像的优势。

## 和另外两族的边界

| | 保守锁步 | 回滚 | 状态同步预测 |
| --- | --- | --- | --- |
| 传什么 | 输入 | 输入 | 状态 + 自己的输入 |
| 别人从哪来 | 等真输入再算 | 本地用（猜或真）输入算 | 服务器坐标插值 |
| 回退谁 | 不回退，先等 | 整份逻辑 | 通常只自己的 pawns |
| 真值 | 齐拍后的输入 | 迟到的真输入 | 服务器快照 |

Rocket League 在载具上用了回滚思想修物理，但对局仍有服务器权威状态。那是混合，不要写成「竞速 = 回滚」。

## 失败模式

| 现象 | 常见原因 |
| --- | --- |
| 对手瞬移、自己正常 | 你这边输入延迟设太低；帧优势没做 |
| 命中火花打出又收回 | 特效在预测帧就播了，确认失败无法撤销 |
| 偶尔整局对错拍 | 存档漏了 PRNG 或输入缓冲 |
| 高 ping 突然不能打 | 超过最大回滚，又没有减速等待 |
| 4 人以上卡顿 | 单帧 F 太重，一次深回滚爆预算 |
| 音效播两遍 | 预测播一次，确认又播一次 |

## 适用边界

适合：2D/3D 格斗、平台对打、逻辑很轻、人数少、必须按键即响应。
不适合：重物理、ragdoll、大世界、FPS 百实体、需要服务器裁迷雾当核心公平。

代表：GGPO、街霸 6、罪恶装备 Strive、Melty Blood、平台格斗 indie。
旧格斗网战的 delay-based 锁步能打，高延迟时全员变钝；新作应迁到回滚，不要把固定迟当作格斗首选。
