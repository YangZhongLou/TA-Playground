# 配套技术

主线方案只回答「传输入还是传状态」。手感、带宽、公平靠下面这些叠上去。
同一技术可以出现在不同主线上：帧同步用插值做表现；状态同步用预测做自己的角色；
回滚用存档做整局重演。选型时不要把配套技术喊成一种「同步方案」。

## 客户端预测与和解

只预测**自己拥有的对象**。预测别人是在猜别人的输入，那是回滚的正式做法。

### 预测循环

1. 采样输入，立刻推进本地模拟，渲染用这份结果。
2. 输入带单调序号发给权威端，本地推进「未确认队列」。
3. 权威结果带着「已处理到序号 x」回来。
4. 把本地状态换成 x 时刻的权威状态。
5. 按顺序重放队列里 x 之后的输入，直到当前。
6. 重放结果与正在显示的位姿比较：误差小则平滑纠正，大则硬拉。

### 必须进存档的东西

重放若缺状态，就会「修一次错一次」。至少包括：位置、速度、姿态、地面/跳跃标志、
与预测有关的冷却和技能阶段、碰撞用的几何（用历史的，不用现在的墙）。
动画根运动若参与移动，动画状态也要能重放，或移动不要交给动画。

### 常见错误

| 错误 | 结果 |
| --- | --- |
| 重放用当前世界碰撞 | 墙已经碎了，重放穿过去，下一包再弹回 |
| 预测了不该预测的技能 | 服务器否决后火箭消失、护盾闪没 |
| 两个客户端预测同一物体 | 互拉 |
| 把预测当权威 | 客户端改内存就能改结算——除非服务器根本不听 |

状态同步里的预测，真值是服务器快照。回滚里的「预测」，真值是迟到的远程输入。
实现都像「存档 + 重演」，对齐的对象不同。

## 插值与外推

远程物体的显示时刻故意落后真实世界，以便夹在两份已到达的状态之间。

### 插值

已知状态 A(tA)、B(tB)，显示时刻 tShow ∈ [tA, tB]：

`alpha = (tShow - tA) / (tB - tA)`，位姿 = lerp(A, B, alpha)。

旋转用 slerp 或最短弧。不要对欧拉角逐分量 lerp，会万向节跳。

tShow 怎么取：`tShow = 估计的服务器现在 - interpDelay`。
Source 默认 delay ≈ `cl_interp_ratio / cl_updaterate`。ratio=2、20Hz 发送 → 约 100ms。

### 外推

tShow 比最新状态还新：按最后速度 `p + v * dt` 往前估。急停会滑出，下一状态拽回。
缓冲充足时不要外推。混合策略：有 B 就插值，没有才外推。

### 窗怎么选

窗 < 一拍发送间隔 + 典型抖动：经常断，只能外推。
窗过大：近身互打对在过去的残影上。射击因此另做滞后补偿，而不是把窗加到 300ms。

帧同步的表现层也可以插值：在逻辑拍 S(n) 与 S(n+1) 之间平滑。那不改变结算，只改观感。

## 滞后补偿

只适用于「攻击者看到的世界比服务器现在旧」的射击判定。命令式 MOBA、格斗回滚一般不靠它。

### 步骤

1. 客户端开火，带上自己的时间戳或 Tick。
2. 服务器计算攻击者当时的画面时刻：大约 `now - ping/2 - interpDelay`（具体以引擎为准）。
3. 把受害者（及需要的几何）倒带到该时刻。
4. 做射线 / 体积检测。
5. 把世界转回现在，应用伤害。

### 限制

- 历史缓冲长度 ≥ 最大允许倒带。再长就截断。
- 粗测包围体先剔，再精确倒带，省 CPU。
- 超过阈值改外推或拒绝（守望先锋公开量级约 220ms）。
- 保护的是射击者，牺牲的是被射者进掩体的手感。这是产品选择，不是实现失误。

倒带的是服务器保存的权威历史，不是客户端发来的「我看到他在这」。客户端报的位置只能当提示，不能当证据。

## 兴趣管理

不问「世界有什么」，问「这条连接需要知道什么」。

| 方法 | 做法 | 坑 |
| --- | --- | --- |
| 距离球 | 半径内发 | 角落隔墙仍发；半径边缘弹出 |
| 网格 / 九宫 | 订阅所在格 + 邻格 | 格太大等于没裁；太小抖动进出 |
| 视野 / 遮挡 | 墙后不发 | CPU 贵；突然现身要有表现 |
| 队伍 | 队友始终相关 | 不要把敌人做成始终相关 |
| 优先级 | 交战 > 附近 > 装饰 | 要有每连接字节预算才能生效 |
| 休眠 | 不动的对象停更 | 唤醒要带初始全量，否则对方没有门 |

帧同步的逻辑层常常仍是全图 F。AOI 只能裁表现和下行，裁不掉「本地其实算了全图」。
要让雾外坐标不存在于客户端，必须状态同步 + 服务器不发。

相关性切换时物体会「突然出现」。需要出生过渡，或在进入相关前就发低频粗状态。

## 量化、增量、优先级

砍带宽的顺序固定：**不发 > 少发 > 发得小**。先上 AOI 再抠 bit。

### 量化

位置：世界划定包围盒，映射到 16 bit（或 xz 16 + y 更少）。盒子外的对象先钳制或换高精度。
旋转：小三元或量化四元数，不要三个 float。
布尔和枚举：打包进位域。
速度：范围小，可用比位置更少的 bit。

量化误差会进预测误差。移动快的物体提高频率，比盲目加 bit 更有效。

### 增量

差必须相对「对方 ACK 的基」。ACK 丢失则换更老基或发全量。
相对「上一份发出去的」做差，对方没收到时会解出鬼世界。

### 优先级与预算

每连接每 Tick 的字节上限。超限按分排队：正在瞄准你的敌人 > 附近移动体 > 远处门。
被饿太久的对象提高优先级，避免门永远不更新。

## 时间同步

状态同步认服务器时间戳。锁步和回滚认帧号。两套不要解释同一 Transform。

估计一程延迟：`RTT/2`，RTT 用平滑（指数或中位数），不要被单次尖峰带着跳。
客户端时钟只许慢漂，不许跳变：跳变会让插值 alpha 爆炸、动画倒放。

锁定模拟步长（15 / 20 / 30 / 60 / 128 Hz）比用渲染 delta 推逻辑安全。
渲染跟不上时：一帧跑多个模拟步（守望先锋 30fps 渲染仍 60Hz 模拟）。服务器跟不上会死亡螺旋，必须当性能事故。

## 可靠与不可靠

| 通道 | 用途 | 丢了会怎样 |
| --- | --- | --- |
| 不可靠无序 | 位置、速度、频繁姿态 | 下一快照纠正 |
| 可靠有序 | 结算、背包、关卡阶段、输入帧（锁步） | 必须到达；阻塞后续可靠消息 |
| 不可靠有通知 | 少见 | 引擎未必提供 |

锁步的 I(n) 必须可靠有序：缺拍不能跳。用 UDP + 帧号 + 冗余 + 补发，不要用 TCP 慢启动。
状态同步的姿态必须不可靠：用可靠通道发位置会在丢包时卡死。

应用层冗余（包里带上前 k 拍输入或前一份增量）往往比「丢了再等重传」更适合游戏。
TCP 保证到达，但不保证何时到达。游戏在乎何时。

## 这些技术叠在哪条主线上

| 技术 | 帧同步 | 状态同步 | 回滚 |
| --- | --- | --- | --- |
| 预测自己 | 一般不用（逻辑等输入帧） | 射击刚需 | 自己的输入本来就立刻进 F |
| 预测别人 | 不用 | 默认不用 | 正式机制 |
| 表现插值 | 常用 | 远程物体刚需 | 确认后可平滑回滚痕迹 |
| 滞后补偿 | 通常无准星，不用 | 射击刚需 | 同一帧互打，不用这套 |
| AOI 裁逻辑 | 裁不掉全图 F | 可让雾外无数据 | 同锁步，本地有全图 |
| 输入冗余 | 刚需 | 预测输入窗口常用 | 刚需 |
| 状态增量 | 仅检查点 / 重连 | 刚需 | 仅重连快照 |

叠错的典型：在帧同步里做 C/S 预测拉扯（角色发飘）；
在状态同步里用可靠 RPC 发位置；
在回滚里把粒子当逻辑状态存档（存不起、收不回）。
