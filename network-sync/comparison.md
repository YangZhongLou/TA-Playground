# 方案优劣与品类对照

没有全局最优。帧同步赢在「单位很多、输入很小」；状态同步赢在「权威、规模、随时进出」；回滚赢在「按键即打击」；引擎复制赢在「交货速度」。下面按机理对比，再落到品类。

四套方案的实现细节见 `schemes/`。本篇只回答：各方案赢在哪、死在哪、哪类游戏该用。

## 对比轴

用同一组轴衡量，避免「A 比带宽、B 比手感」各说各话。

| 轴 | 问的是什么 |
| --- | --- |
| 带宽如何随规模涨 | 多一个单位、多一个玩家，包会涨多少 |
| 本地手感 | 按下按键到自己角色响应要等多久 |
| 互打公平 | 双方是否在同一模拟时刻互相作用 |
| 确定性成本 | 逻辑能不能直接用引擎物理 / 动画 |
| 权威与作弊 | 客户端能不能看见不该看的，能不能改结果 |
| 会话弹性 | 中途加入、断线重连、观战、分线难不难 |
| 人数上限 | 谁先爆：带宽、对齐等待、存档、服务器 CPU |
| 工程成本 | 第一周能跑 vs 上线三个月后还在修不同步 |

## 帧同步

网络只发输入。每个模拟端用同一份确定性逻辑把世界推出来。

### 帧同步赢在哪

带宽与战场实体数几乎无关。1000 个小兵和 10 个小兵，线上走的仍是「几个玩家这一帧点了什么」。RTS、自走棋、MOBA 兵线吃的是这个性质。

全场逻辑天然一致。录像、观战、复盘、争议回放都是重放输入，不必另存一份世界录像。结算争议可以对着同一份输入重跑。

传输层简单。包体小、语义少，匹配和转发服务器可以不跑玩法。服务器若只做转发与校验，单局成本低于「服务器模拟全场并给每个人裁快照」。

技能与数值按帧结算，不需要为远程单位做插值猜测。设计师写的 CD、弹道、碰撞框在各端是同一时刻的同一结果。

### 帧同步死在哪

操作延迟绑在最慢的那个人身上。保守锁步必须等齐输入，手感 ≈ 一程延迟 + 对齐缓冲。射击、格斗这种「按下就要打中」的玩法会发糊。

确定性是长期税，不是启动税。浮点、无序容器、多线程、动画通知、物理、跨 ARM/x86 编译器，任何一处分叉都会无声跑偏。商业项目往往把逻辑重写成定点 + 单线程 ECS，等于放弃引擎自带模拟。

一人卡全员卡。掉线、卡顿、弱网要么拖慢整局，要么踢人 / AI 托管。这是锁步人数很难上到 20+ 的主因。

每个客户端都持有完整世界。战争迷雾只是表现层过滤，透视、全图、本地改伤害的面比状态同步大。服务器必须另跑一份模拟做校验，否则竞技局不可信。

中途加入、重连、观战要额外做快照或从头重放。纯锁步没有「发你一份当前世界」。人一多，重放太慢，必须掺状态快照，纯度就被打破。

客户端 CPU 替代了网络。单位从网络卸载后，全部砸在每台设备的逻辑帧上。低端机成为全场帧率上限。

### 帧同步适合

| 品类 | 原因 | 代表 |
| --- | --- | --- |
| RTS | 单位成百上千，输入却是点选与指令 | 星际争霸、帝国时代 |
| 手游 MOBA | 兵线 + 技能前摇能掩盖等帧；端上 CPU 够跑 10 人局 | 王者荣耀、决战平安京 |
| 自走棋 / 自走战棋 | 棋子多、操作低频、回合节奏本身就有缓冲 | 金铲铲、云顶之弈 |
| 实时卡牌对战 | 输入是出牌，状态由规则引擎推演 | 皇室战争 |
| 部分回合制战术的「即时演出」 | 指令阶段可等，演出阶段要各端一致 | 带帧同步演出的战棋 |

PC 端 MOBA（英雄联盟、Dota 2）走状态同步，不走帧同步。原因是英雄操作更跟手、服务器权威反作弊、随时观战与重连是产品需求。不要把「MOBA」当成帧同步的同义词。

### 帧同步不适合

| 品类 | 原因 |
| --- | --- |
| FPS / 英雄射击 | 等帧毁掉射击手感；滞后补偿模型也对不上 |
| 大逃杀 / MMO | 人数与随时进出直接撞上对齐等待和全量本地模拟 |
| 格斗 | 能用，但是延迟锁步（delay-based）已被回滚淘汰 |
| 载具 / ragdoll / 破坏物理 | 引擎物理不确定，自研确定性物理成本通常高于玩法价值 |
| 开放世界 | 实体生命周期、流式加载与「全端同一模拟」冲突 |

## 状态同步

服务器持有权威世界，下行快照或增量。客户端插值别人、预测自己。

### 状态同步赢在哪

服务器说了算。伤害、击杀、拾取、移动合法性都在服务器落地。客户端改本地内存不能改结果。AOI 还可以根本不发看不见的人，这是反透视的第一道闸。

不要求确定性。引擎物理、动画图、导航、第三人称控制器可以直接用。这是它成为 UE / Unity 默认路径的原因。

会话弹性最好。中途加入发一份快照；断线重连再发一份；观战订同一份状态流；分线、副本、无缝切换都是「换相关集」，不必重放整局输入。

规模靠裁剪，不靠「所有人算所有东西」。距离、格子、队伍、休眠、频率、优先级，把 O(实体 × 玩家) 砍到「每人只看到自己那一碗」。百人空投、开放世界、MMO 都靠这个活。

本地角色可以预测到接近单机。远程物体用插值换平滑。射击再叠加滞后补偿，把「我准星上有人」和「服务器同意打中」对齐。手感与公平可以分开调。

丢包能自愈。位置丢了，下一份快照会纠正。不像可靠 RPC 把姿态卡在队头。

### 状态同步死在哪

带宽和服务器 CPU 随「相关实体 × 连接数」涨。没有 AOI 的状态同步，单位一多先于玩法死掉。RTS 小兵精确同步走这条路会先把带宽打满。

远程玩家永远画在过去。插值窗口通常几十到一百多毫秒。你看见的敌人不是他此刻的位置。近身互打、格斗、精确弹反会感觉「对在空气上」。

预测只覆盖自己拥有的对象。载具换座、推箱子、抢同一扇门、技能带位移碰撞，全是和解边缘。预测错了会橡皮筋回弹，玩家归咎为「网络卡」，本质是权威与本地分叉。

滞后补偿保护射击者，牺牲被射者。已经闪进掩体仍被击杀，是这套模型的结构后果，不是单纯的 bug。窗口必须封顶，否则高延迟变成瞄准过去。

两套时间是常态：服务器权威时间、客户端插值时间、本地预测时间。技能、动画、命中特效必须声明自己跟哪一套走。漏声明就会「客户端已击杀、服务器未到」。

实现「能跑」很快，「跑对」很慢。快照基 ACK、量化、休眠、优先级、所有权切换，每一项都是上线后的线上事故来源。

### 状态同步适合

| 品类 | 原因 | 代表 |
| --- | --- | --- |
| FPS | 服务器权威 + 预测 + 滞后补偿是射击标准解 | CS、Valorant、COD |
| 英雄射击 / TPS | 技能状态用属性复制，位移用预测 | 守望先锋、Apex |
| 大逃杀 | 百人稀疏空间，靠 AOI 与复制图 | Fortnite、PUBG |
| MMO / 开放世界 | 随时进出、实体海量但不都活跃 | WoW、原神、荒野行动类 |
| 合作 PVE | 4 人、物理与动画要现成、主机或专用服都行 | L4D、怪物猎人集会所 |
| 载具射击 / 大战场 | 物理权威在服务器，客户端修表现 | Battlefield、战争雷霆 |
| 生存制作 / 沙盒会话 | 世界持久、交互杂、人可进出 | Valheim、ARK、Minecraft 多人 |
| 不对称杀手 | 视野差是玩法，必须服务器裁信息 | 黎明杀机 |
| 动作冒险联机 | 需要掉线重连和引擎物理 | 艾尔登法环联机、灵魂系 |

### 状态同步不适合

| 品类 | 原因 |
| --- | --- |
| 单位极多的 RTS | 每兵一份状态，带宽和 AOI 都救不了「全图精确」 |
| 格斗 | 插值后的对方不是同一帧的碰撞框 |
| 要帧级互打的平台对战 | 同上；应用回滚 |

「不适合」指当主线。大厅、匹配、聊天、结算用状态或 HTTP，与对战主线无关。

## 回滚

乐观锁步：先用预测输入往下跑，真输入迟到再倒回重演。传的仍是输入，不是对方坐标。

### 回滚赢在哪

本地输入延迟接近 0。格斗游戏的按键、取消、反制要求帧级响应，锁步的等齐不可接受，状态同步的插值又对不齐碰撞框。回滚同时满足「立刻动」和「同一模拟里互打」。

带宽仍是输入级。两人 60Hz 只交换按键位，比状态快照小一个数量级。

公平模型干净。双方最终都在同一确定性世界里结算，没有「我打你的插值残影」。录像仍是输入重放。

相对纯锁步，弱网时游戏仍能继续。卡的人多回滚，而不是全场冻结。这是现代格斗线上从 delay-based 迁过来的原因。

### 回滚死在哪

三重硬条件同时成立：确定性、每帧可存档、逻辑与表现分离。缺一项就回滚一次坏一次。引擎自带物理、动画通知、音效、粒子都不能在预测帧里产生不可撤销副作用。

存档与重演吃 CPU。一次 8 帧回滚等于瞬间重跑 8 份逻辑。单帧必须极轻。ragdoll、破坏、布料、复杂导航一上来，预算就没了。

人数指数变差。每人一份预测输入，人数上升后错误预测组合变多，存档变大，公平延迟策略也更难。2～4 人是舒适区，8 人要克制设计，再往上通常不该选回滚当主线。

高延迟会突然「可见」。低于阈值时玩家以为在打单机；超过约 8 帧（60Hz 下约 130ms）后人物传送、命中收回、动画闪回，体感断崖。没有平滑的中间档。

调试极差。只在预测失败时出现的 bug，本地开房复现不了。音效播两遍、命中停顿打在错误帧、特效无法收回，全是表现层没跟确认层分开的典型事故。

透视面与锁步相同。完整世界在本地。中途加入同样要快照或重放。

### 回滚适合

| 品类 | 原因 | 代表 |
| --- | --- | --- |
| 2D / 3D 格斗 | 帧级互打 + 零输入延迟是品类底线 | 街霸 6、罪恶装备、GGPO 系 |
| 平台对打 | 跳跃与攻击同一套碰撞框 | Smash 类、平台格斗 indie |
| 轻量确定物理的体育 / 球类 | 模拟够小才能每帧存档 | 部分 2D 球类、独立体素体育 |
| 需要「按键即响应」的 1v1 动作 | 人数少、逻辑纯 | 部分动作对打 |

Rocket League 用了回滚思想修载具物理，但对局仍有服务器权威状态。它是混合，不是「竞速 = 回滚」。

### 回滚不适合

| 品类 | 原因 |
| --- | --- |
| FPS / BR / MMO | 实体与物理体积远超可重演预算；中途加入是产品功能 |
| RTS / 自走棋 | 不必零延迟；确定性锁步更简单，少一套存档管线 |
| 开放世界 / 破坏物理 | 状态太大，存档拷不起 |
| 4 人以上技能射击 | 预测组合与技能副作用管不过来 |

老式格斗网战用延迟锁步（双方加固定缓冲）。能打，但高延迟时所有人变迟钝。新作把这类玩法迁到回滚，不要再把 delay-based 当格斗首选。

## 引擎对象复制

状态同步的工业接口：按 Actor / Networked Object 声明属性、RPC、频率、相关性。UE Replication、Unity NGO、Mirror、Fish-Net、Photon Fusion 的 State 模式同属这一族。

它不改变状态同步的物理定律，改变的是工程成本和可调性。和「手写整世界快照」对比才有意义。

### 引擎复制赢在哪

交货快。角色、血量、门开关用复制属性；开火、拾取用 RPC。
UE 现在用 **Mover** + Network Prediction 做「自己人怎么动」；CMC 是旧的 `ACharacter` 路径。GAS Prediction Key 仍是技能那本账。

对象级调控开箱：OwnerOnly、SkipOwner、休眠、更新频率、优先级。手写快照要自己做分块和订阅，复制模型把这些挂到对象上。

与引擎生态一体。动画、物理约束、关卡流送、调试器、Profiler 都认 Actor。TA 与玩法程序员共用同一套对象，而不是维护平行的「网络实体」。

### 引擎复制死在哪

抽象泄漏。Role、Owner、Relevancy、Dormancy、可靠 RPC 队头阻塞，每一个都是「看起来设对了、线上错了」的坑。问题表现是瞬移、别人改我的血、门只对主机开，根因在对象模型而不是算法公式。

大规模前要换后端。默认 replicator 对每个连接穷举对象。百人同场必须 Replication Graph 或 Iris，等于第二套同步架构。

包布局不透明。量化、字段打包、发送顺序受引擎约束。要抠到 RTS 那种「每兵几 bit」时，对象复制往往不够用，得回到自定义快照。

确定性 / 回滚几乎做不到。复制的是结果不是输入，对象生命周期与反射布局也不适合每帧 memcpy 整份逻辑态。选复制 = 放弃锁步和回滚当主线。

所有权切换是重灾区。载具座位、可拾取武器、可推物体，两个客户端同时以为自己拥有时，预测和解会互相打架。

### 引擎复制适合

| 品类 | 原因 |
| --- | --- |
| 绝大多数 UE / Unity 动作与射击 | 默认路径，补预测与 AOI 即可 |
| 合作 PVE、会话型生存 | 对象杂、交互多，复制属性比自研序列化便宜 |
| 需要快速验证的联机原型 | 本仓库若做联网，从这里开始 |

### 引擎复制不适合

| 品类 | 原因 |
| --- | --- |
| 要做确定性竞技逻辑的 RTS / 格斗 | 复制的是状态结果，重演不了输入 |
| 自定义 bit 级协议的重度优化项目 | 引擎序列化是瓶颈也是黑盒 |
| 纯锁步中间件项目 | 用 Photon Quantum 或自研 ECS，不要再套一层 Actor 复制当逻辑源 |

Photon Quantum 是帧同步中间件，不是对象复制。Fusion 的主机模式才是这一族。名字带 Photon 不能当选型结论。

## 同轴对照

| 轴 | 帧同步 | 状态同步 | 回滚 | 引擎复制 |
| --- | --- | --- | --- | --- |
| 传什么 | 输入 | 状态 / 增量 / 事件 | 输入 | 按对象切的状态 + RPC |
| 带宽 vs 单位数量 | 几乎不涨 | 近似线性，靠 AOI 砍 | 几乎不涨 | 同状态同步 |
| 带宽 vs 玩家数 | 输入对齐成本涨 | 快照订阅涨 | 预测组合涨 | 连接 × 相关对象 |
| 自己的输入延迟 | 高（等齐） | 可接近 0（预测） | 接近 0 | 同状态同步 |
| 看见别人 | 同一逻辑帧 | 插值后的过去 | 本地重演出的对方 | 插值后的过去 |
| 互打是否同一帧 | 是 | 否（靠补偿近似） | 是 | 否 |
| 确定性 | 全程必须 | 不必须 | 重演段必须 | 不必须 |
| 引擎物理 | 基本不能直接用 | 友好 | 不能直接用 | 友好 |
| 反透视 | 弱（本地有全图） | 强（可不发） | 弱 | 强（相关性） |
| 改伤害 / 改位置 | 须服务器另跑校验 | 服务器直接拒绝 | 须校验 | 服务器拒绝 |
| 中途加入 | 难 | 易 | 难 | 易 |
| 弱网表现 | 全场变慢或踢人 | 橡皮筋、丢动作 | 画面回闪 | 同状态同步 |
| 人数舒适区 | 2～10 | 16～100+ | 2～8 | 同状态同步 |
| 第一周成本 | 中（传输易，确定难） | 低（引擎模板） | 高 | 最低 |
| 上线后成本 | 不同步调试 | 带宽与边界预测 | 回滚表现 bug | Role / 所有权踩坑 |
| 录像 | 输入重放 | 要录状态或演示流 | 输入重放 | 要录状态 |

读表时把「引擎复制」当作状态同步的实现，不要当成第五种物理。它在「第一周成本」和「对象级调控」上赢手写快照，在「bit 级控制」和「确定性」上输。

## 品类总表

首选是主线。可混是常见工程现实。禁止是把该方案当对战核心。

| 品类 | 首选 | 可混 | 禁止当主线 | 理由（一句话） |
| --- | --- | --- | --- | --- |
| RTS | 帧同步 | 重连快照 | 纯状态同步 | 单位太多，状态发不起 |
| 手游 MOBA | 帧同步 | 大厅与结算走状态 | 回滚 | 兵线 + 前摇掩盖等帧；技能副作用不适合回滚 |
| PC MOBA | 状态同步 | 关键技能预测 | 纯帧同步 | 跟手操作与观战重连是产品需求 |
| 自走棋 | 帧同步 | 观战快照 | 回滚 | 操作低频，单位多 |
| 实时卡牌 | 帧同步或服务器权威回合 | — | 回滚 | 输入是指令，不必零延迟重演 |
| 回合制 RPG / 战棋 | 服务器权威请求-响应 | 演出用锁步 | 实时回滚 | 不是实时同步问题 |
| FPS | 状态同步 + 预测 + 补偿 | 复制图 / Iris | 帧同步、回滚 | 权威判定 + 本地枪感 |
| 英雄射击 | 状态同步 + 技能预测 | GAS / 能力复制 | 帧同步 | 位移技能要预测，爆炸物要权威 |
| TPS 动作射击 | 状态同步 | 载具单独调频率 | 回滚 | 同 FPS，物理更重 |
| 大逃杀 | 状态同步 + AOI | Iris / Graph | 帧同步 | 百人稀疏，必须裁视野 |
| 格斗 | 回滚 | 大厅状态 | 状态同步插值互打 | 碰撞框必须同一帧 |
| 平台对打 | 回滚 | — | 状态同步 | 同格斗 |
| 延迟锁步格斗 | 仅维护老作 | — | 新作首选 | 高延迟时全员变钝 |
| 载具竞速 | 状态同步 | 轻量物理可回滚 | 保守帧同步 | 物理重则权威；要零延迟才上部分回滚 |
| 大战场载具射击 | 状态同步 | 休眠建筑 | 帧同步 | 物理 + 人数 + 进出图 |
| 体育（足球等） | 看物理：确定则回滚 / 锁步，否则状态 | 混合 | — | 先量单帧模拟能不能存档重跑 |
| 合作 PVE（2～4） | 引擎复制 | Listen Server | 帧同步（无必要） | 交货速度压倒带宽理论 |
| 生存制作 | 引擎复制 + 休眠 | 分块 AOI | 回滚 | 世界杂、人进出、交互多 |
| 沙盒创造 | 状态 / 复制 | 客户端权威建造（须校验） | 回滚 | 持久世界 |
| MMO | 状态同步 + 严格 AOI | 分线、九宫格 | 帧同步、回滚 | 规模与进出是第一约束 |
| 开放世界动作 | 状态同步 + 休眠 | 遇敌小战场切更高频率 | 全图帧同步 | 实体多、同时活跃少 |
| 不对称杀手 | 状态同步 | 严格信息裁剪 | 帧同步 | 信息差是玩法，不能本地有全图 |
| VR 近战 | 状态同步 + 强预测 | 小范围回滚实验 | 保守锁步 | 延迟直接致晕；全场等齐不可接受 |
| 音游对战 | 帧同步或谱面 ID + 输入时间戳 | — | 大世界复制 | 判定跟谱面，不跟角色快照 |
| 社交推理 / 狼人 | 服务器权威事件 | — | 回滚 | 低频离散事件 |
| 塔防联机 | 帧同步 | — | 每怪状态同步 | 同类于 RTS 小兵 |

## 混合时的硬规则

混合是常态，但两套主线不能写同一份 Transform。

| 混合 | 合理切法 |
| --- | --- |
| 开放世界 + 格斗场 | 大世界状态同步；进入 1v1 切回滚，结束再灌回状态 |
| MOBA | 对战核心帧同步；大厅、商城、战报走状态 / HTTP |
| 射击 + 可驾驶载具 | 人都走预测复制；载具所有权切换要单写，禁止两人同时预测 |
| 回滚对打 + 场景物件 | 对打层用帧编号；门、观众、特效用服务器时间 |

时钟隔离写进设计文档。谁拥有位置、谁允许预测、确认前哪些特效能播，三条不写清，混合局必出「死人还能动」。

## 决策顺序

1. **互打是否必须同一帧？** 是 → 帧同步或回滚。格斗 / 平台对打选回滚；RTS / 自走棋选帧同步。
2. **单位是否多到状态发不起？** 是 → 帧同步。
3. **要不要随时加入、分线、服务器裁视野？** 是 → 状态同步（引擎复制）。
4. **能不能放弃引擎物理？** 不能 → 状态同步。
5. **已在 UE / Unity 且要先跑起来？** 走引擎复制，缺什么再补，不要先自研协议。

## 延迟预算

| 玩法 | 可玩 RTT | 和方案的关系 |
| --- | --- | --- |
| 格斗 | < 80～130ms | 回滚；超出后减速等待，体感断崖 |
| 射击 | < 80ms 体感好，150ms 仍可打 | 状态同步 + 预测 + 补偿；Tick 越高判定越稳 |
| MOBA | 100～200ms | 帧同步靠前摇掩盖等帧 |
| RTS | 200ms+ | 帧同步；指令延迟可接受 |
| MMO | 200～400ms | 状态同步；动画与确认提示掩盖 |

这些数字是手感锚点，不是协议硬限制。移动端还要加 Wi-Fi / 4G 抖动余量。

## 本仓库

本仓库是 UE5。默认：服务器权威 + Actor 复制 + 本地预测 + 远程插值。只有明确做 RTS 或格斗原型，才离开这条路。细节见 [unreal.md](unreal.md)。
